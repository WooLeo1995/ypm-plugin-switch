# 音源网关 · YesPlayMusic

[English](README.md) · 简体中文

适用于 [YesPlayMusic](https://github.com/qier222/YesPlayMusic) **3.0.0 及更新版本**的社区插件，非官方插件。

它把「曲库」和「音源」拆成两件事：**曲库**（搜索、首页、歌手、专辑、歌单、歌词）来自网易云的匿名接口，**不需要登录**；**音源**（播放直链）由插件内置的网关从多个第三方音源解析，播放前逐个校验，失败自动切换。插件不登录、不保存凭据、不下载也不分发音频。

## 功能

- **免登录网易云曲库**：歌曲、专辑、歌手、歌单搜索（支持翻页）、搜索联想与热门搜索；首页推荐歌单与推荐新歌；排行榜、最新专辑、分类热门歌单；专辑、歌手、歌单详情；原文与翻译 LRC 歌词。
- **多音源网关**：内置 GDStudio 与酷我音源，按顺序解析播放直链，任一环节失败自动换下一个。
- **播放前可用性校验**：先探测候选直链是否真的可播，过期或失效的地址不会交给播放器。
- **熔断与缓存**：连续失败自动冷却，成功即恢复；同一首歌短时间内失败不会反复请求音源。
- **侧边栏「音源网关」**：查看样例曲目自检结果与当前回退顺序。
- **歌曲右键菜单**（仅对本插件的曲目显示）：复制音源直链、检测音源可用性。
- **九种界面语言**：跟随 YesPlayMusic 的界面语言切换。
- **没有登录入口**：不导出 `account`、`signIn`、`liked` 等需要账号的能力，也不提供会员、购买或下载功能。

## 安装

需要 YesPlayMusic **3.0.0 或更新版本**。插件在应用内置的 QuickJS 里运行，不需要 Node.js、服务端、API 密钥或额外程序。

- **方式一（推荐）**：打开 **设置 → 插件 → 从本地文件夹安装…**，选择包含 `plugin.json` 的插件文件夹。如果拿到的是 ZIP，请先解压；不要只选择 `plugin.json` 文件。
- **方式二**：仓库发布到 GitHub 后，在 **设置 → 插件 → 安装插件** 中粘贴仓库地址，形如 `github.com/<owner>/ypm-plugin-switch`，把 `<owner>` 换成实际仓库所有者。当前项目不内置远程仓库地址；也支持宿主提供的 Release、ZIP 或 `plugin.json` 链接，详见 [插件开发指南](https://github.com/qier222/YesPlayMusic/blob/main/docs/plugins.md)。

安装前应用会列出插件需要的网络权限（网易云 eapi、GDStudio、网易云 CDN、酷我搜索 / 波点 / 移动 / CDN）。确认并启用后，在 **设置 → 插件 → 音乐来源** 中选择「音源网关」，或点击侧边栏左下角的头像切换。

## 使用

1. 选择音乐来源「音源网关」后，搜索、首页、专辑、歌手和歌单页都来自网易云曲库。
2. 双击歌曲播放。网关先用匿名接口补全歌名、歌手与时长，再按顺序向音源要直链，探测通过后交给播放器。
3. 侧边栏的 **音源网关** 页可以查看每条音源的自检结果与当前回退顺序。
4. 歌曲右键菜单里的 **复制音源直链** 会解析并复制当前可用直链；**检测音源可用性** 会立即尝试一次并提示结果。

曲库与音源是两个独立的层：曲库里有歌，不代表第三方音源一定有它的版权或可匹配资源。若某首歌在所有已启用音源处都取不到可播直链，插件会明确提示「没有可用音源，请稍后重试」，播放器会跳过这首歌。这是预期行为，不是故障。

## 音源与回退顺序

「音源」指第三方音频直链提供方；本插件的曲库并不来自它们。

默认顺序：

1. **GDStudio**（按网易云歌曲 ID 取址）
2. **酷我**（波点 `audioUrl` 接口）
3. **酷我移动**（移动端 `convert_url2` 接口）
4. **GDStudio 搜索**（按歌名 + 歌手搜索后严格匹配）

按 ID 取址的链路最快、命中率最高；酷我的两条链路互相补充；关键词搜索放在最后，因为它需要匹配歌曲版本、歌手和时长，代价更高，也更容易被错版本干扰。两条关键词链路只有在歌名、版本限定语、歌手重合，且双方都有时长时相差不超过 8 秒，才会采用结果；宁可放弃也不把伴奏、DJ 版或翻唱当成原曲。

- **优先音源**设为「GDStudio 优先」时，两条 GDStudio 链路排到酷我前面；设为「酷我优先」时，酷我链路先尝试；「自动」使用上面的默认顺序。
- **停用 GDStudio 音源** 或 **停用酷我音源** 会把整族音源从尝试列表中剔除；两族都停用时播放会提示在设置中至少启用一个音源。
- 一次播放尝试的总预算约 22 秒，单个音源内部的请求会按剩余预算收紧超时。

失败与回退：

- 音源没有匹配到歌曲（返回空）是软失败，直接尝试下一个，不触发冷却。
- 网络错误、超时、5xx / 429、响应无法解析，或返回的直链探测失败，是硬失败：计入该音源的熔断，并继续尝试下一个。
- 普通 4xx（例如接口不支持该请求）按软失败处理。
- 全部音源失败后会记录 45 秒的失败短缓存，期间同一首歌、同一音质直接提示「没有可用音源，请稍后重试」，不再反复请求上游。

## 播放前校验与熔断

- **探测**：优先发 `HEAD` 请求。2xx 且内容类型为音频 / 视频 / `application/octet-stream`，或带有 `Content-Length`，视为可播放；返回 `text/html`、JSON、XML 等错误页视为失效（过期签名常见这种表现）。`HEAD` 被拒绝（403 / 405 / 501）或网络出错时，退化为 `Range: bytes=0-0` 的 `GET` 再确认一次。2xx 但没有任何类型或长度信息时也会采信，避免误杀正常 CDN。4xx / 5xx、超时和网络错误都判为不可用。
- **直链缓存**：成功解析的直链会在内存中复用最多 10 分钟；校验时间在 2 分钟内的直链直接返回，超过 2 分钟会重新探测，失效则丢弃并重新解析。
- **熔断**：同一音源连续第 1 / 2 / 3 次硬失败分别冷却 30 秒 / 2 分钟 / 10 分钟，成功一次即清零。健康状态保存在插件数据目录中，重启应用后仍然有效。
- **跳过播放前校验**（设置项）：默认关闭。打开后不再探测直链，直接采信音源返回值，可能把已失效的链接交给播放器，只建议在排查问题时临时使用。
- **自检不写熔断状态**：侧边栏的自检是只读操作，不会影响正常播放时的音源排序。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 音质 | 跟随播放器 | 可选「标准 (128k)」「高音质 (320k)」「无损 (FLAC，可用时)」。设置优先于播放器传入的音质；实际拿到什么取决于音源返回，不可用时会向低档回退。 |
| 优先音源 | 自动 | 「自动」「GDStudio 优先」「酷我优先」。只调整音源族的尝试顺序，不保证某个音源一定可用。 |
| 跳过播放前校验 | 关闭 | 打开后跳过直链探测，可能遇到失效链接。 |
| 停用 GDStudio 音源 | 关闭 | 停用后只使用酷我音源。 |
| 停用酷我音源 | 关闭 | 停用后只使用 GDStudio 音源。 |

布尔设置在未改动时是关闭状态；两个音源族可以同时停用，但那样无法播放，插件会提示至少启用一个。无损 FLAC 只在音源确实返回 FLAC 时提供：请求无损时 GDStudio 会先要 FLAC，拿不到再退 320k MP3；酷我链路只请求 MP3，因此通常最高为 320k。

## 音源网关自检页

侧边栏的 **音源网关** 页包含两块内容：

- **音源自检**：对每个已启用音源，各用一首固定的样例曲目做端到端解析，并探测返回的直链。不同音源使用不同样例（GDStudio 与酷我两条链路的样例不同），避免某家曲库的版权波动把「没搜到样例」误判成「接口坏了」。每次重新进入本页都会再次检测，结果包含是否可用、耗时与原因。关键词音源如果接口可达、只是样例曲目未命中，会标记为可用并注明「接口可达，样例曲目未命中」——这表示链路本身正常，而不是播放失败。
- **回退顺序**：按当前设置列出网关尝试音源的顺序，编号从 1 开始。

设置弹窗里的「测试连接」（YesPlayMusic 3.1.0 起提供）也会运行同一套自检：全部可用时提示可用数量，有失败时提示不可用数量，没有任何启用音源时提示去设置中启用。

自检只用固定的样例曲目，通过自检不代表所有歌曲都有音源；反过来，某一条链路自检失败也不代表其他音源不可用。

## 常见问题

**某首歌一直提示「没有可用音源，请稍后重试」？**
说明所有已启用音源都没有这首歌的可播资源，或返回的直链都失效了。常见原因是第三方音源没有该曲版权、只有翻唱 / 伴奏（会被严格匹配拒绝），或上游临时限流。这是预期行为：插件不会用试听片段或翻唱冒充原曲，也不会尝试绕过官方鉴权；稍后可以重试。

**所有歌都放不了？**
先打开侧边栏「音源网关」看自检结果，确认网络能访问相关域名（如有代理，请确认代理对插件请求生效）；再检查是否在设置里同时停用了 GDStudio 和酷我。第三方接口偶尔波动，可稍后重试。

**为什么选「无损」拿到的不是 FLAC？**
音质是请求偏好，不是保证。第三方音源是否提供无损取决于歌曲、版权与上游策略；酷我链路只请求 MP3。插件会在可用档位内尽量满足，不会用试听片段冒充完整歌曲。

**需要登录吗？会员歌曲能解锁吗？**
不需要登录，插件不接入账号体系，也没有会员、购买或下载功能。能否播放只取决于第三方音源是否有该曲的可匹配直链；很多在官方客户端里需要会员的歌曲，只要第三方音源有资源就能播放，没有时会明确提示。插件自身不做鉴权绕过，播放能力完全取决于第三方音源是否提供该曲的可播直链。

**自检里「接口可达，样例曲目未命中」是什么意思？**
关键词音源能正常搜索、只是没在它的曲库里匹配到样例曲目，说明链路可达，会显示为可用；真正的播放仍取决于具体歌曲能否匹配到可播资源。

**插件会下载或缓存音频吗？**
不会。音频由 YesPlayMusic 的播放器直接向音源返回的 CDN 地址请求；插件只对候选直链做可用性探测，缓存的是直链、元数据和健康状态，不保存音频文件。

## 隐私与合规

- **不登录**：不请求、不保存任何账号凭据、Cookie、Token 或密码；曲库请求使用匿名 eapi。
- **播前校验**：只对候选直链发一次轻量探测（`HEAD`，必要时 1 字节 `Range GET`），不读取完整音频。
- **最小网络访问**：插件只访问 `plugin.json` 声明的域名（网易云 eapi、GDStudio、网易云 CDN、酷我搜索 / 波点 / 移动 / CDN）。
- **不下载、不分发音频**：只解析直链并做可用性探测；播放由宿主播放器完成。插件不包含、不缓存、不重新分发任何音频文件。
- **本地数据**：插件数据目录里只保存随机生成的设备标识与音源健康状态；直链缓存和失败短缓存只在内存中，应用退出即消失。
- **第三方服务**：请求会到达上述第三方接口，它们可能按自己的策略记录请求信息，适用各自的服务条款与隐私政策。请遵守服务条款与当地法律，曲库元数据及音频版权归原权利人所有。

## 开发

代码结构见 [ARCHITECTURE.md](ARCHITECTURE.md)：`index.js` 是宿主导出入口，`catalog/` 是匿名曲库，`gateway/` 是音源网关，`stream.js` 负责播放前补全元数据，文案在 `i18n.js` 与 `locales/`。

离线测试不访问真实网络，使用 mock 宿主与可编程 `fetch`（Node.js 22+）：

```sh
node --experimental-vm-modules --test test/*.test.mjs
```

需要验证真实链路时，手动运行实网冒烟脚本。它会访问第三方接口，结果受网络环境影响，且不会打印带签名的完整直链：

```sh
node scripts/live-check.mjs            # 实网冒烟
node scripts/live-check.mjs --verbose  # 同时输出插件日志
```

脚本会先校验 `plugin.json` 的网络权限是否覆盖运行期请求主机，再跑通搜索、三档音质、无源歌曲、直链缓存与自检等检查；全部通过时退出码为 0。

插件接口参考 [YesPlayMusic 插件开发指南](https://github.com/qier222/YesPlayMusic/blob/main/docs/plugins.md)。修改文案后请同步补齐 `locales/` 下的九种语言，并运行本地化测试。
